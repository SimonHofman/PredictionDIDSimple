## 1. 引言

本文档说明本项目 **Foundry 单元测试** 的目录结构、设计原则、运行方式，以及与既有 **Hardhat 测试** 的分工关系。测试源码位于 `test/foundry/`，采用 Solidity 编写，覆盖 Phase2（parimutuel + 时间锁预言机）与 Phase3（CPMM + 多结果 + 多签预言机）全部核心合约。

### 1.1 设计目标

| 目标 | 实现方式 |
|------|----------|
| **隔离性** | 每个测试函数运行前 `setUp()` 重新部署合约，不共享可变状态 |
| **可重复性** | 使用 `makeAddr` 确定性地址、`vm.warp` 控制时间，无随机外部依赖 |
| **全面性** | 六类用例：部署 / 功能 / 边界 / 错误 / 事件 / Gas |
| **可读性** | 统一命名前缀 + 分区注释 + 中文 NatSpec 说明测试意图 |

### 2.2 Foundry 配置（`foundry.toml`）

```toml
[profile.default]
src = "contracts"           # 合约源码目录
test = "test/foundry"       # 测试目录（仅扫描 .t.sol）
out = "out"                 # 编译输出（与 Hardhat artifacts 分离）

evm_version = "cancun"
optimizer = true
optimizer_runs = 200
remappings = [
    "@openzeppelin/=node_modules/@openzeppelin/",
    "forge-std/=lib/forge-std/src/",
    "contracts/=contracts/",
```

- `src` 指向现有 `contracts/` 子目录，**无需复制合约**。

- OpenZeppelin 复用 `node_modules`，与 Hardhat 依赖一致。
- 编译器版本、优化参数与 `hardhat.config.js` 对齐。

## 3. 测试设计

### 3.1 设计原则

```
┌─────────────────────────────────────────────────────────┐
│                    每个 test_* 函数                      │
│  ┌─────────┐  ┌─────────┐  ┌─────────┐  ┌─────────┐    │
│  │ setUp() │→ │  Arrange│→ │   Act   │→ │ Assert  │    │
│  │ 独立部署 │  │ 准备状态 │  │ 调用合约 │  │ 验证结果 │    │
│  └─────────┘  └─────────┘  └─────────┘  └─────────┘    │
└─────────────────────────────────────────────────────────┘
```

1. **隔离性**：Foundry 默认每个 `test_*` 前执行 `setUp()`，链上状态归零。
2. **可重复性**：不依赖区块高度以外的环境变量；时间用 `vm.warp` 快进。
3. **全面性**：六类场景分区编写，见 3.2 命名规范。
4. **可读性**：函数名即文档；分区用 `// ===` 注释块标识。

### 3.2 命名规范

| 前缀 | 类别 | 示例 |
|------|------|------|
| `test_Deploy_` | 部署测试 | `test_Deploy_immutableFields` |
| `test_Buy_` / `test_Create_` / `test_Resolve_` | 功能测试 | `test_Buy_yesUpdatesPool` |
| `test_Buy_minimumAmount` | 边界测试 | 最小金额、2/8 outcome、单侧池 |
| `test_RevertWhen_` | 错误测试 | `test_RevertWhen_buyAfterEndTime` |
| `test_Event_` | 事件测试 | `test_Event_bought` |
| `test_Gas_` | Gas 测试 | `test_Gas_buy` |

### 3.3 六类测试说明

#### （1）Setup（准备）

- 基类 `setUp()` 创建账户。
- 子类 `setUp()` 调用 `super.setUp()` 后部署业务合约。
- 使用 `vm.prank(addr)` / `vm.startPrank` / `vm.stopPrank` 模拟调用者。
- 使用 `vm.warp(timestamp)` 模拟时间流逝（时间锁、截止下注）。

#### （2）部署测试

验证构造函数参数、immutable 字段、初始枚举状态（`Status.Open`）、版本号等。

#### （3）功能测试

覆盖主流程：

- **Phase2**：`buy` → `resolve` → `claim`；`voidMarket` 退款。
- **Phase3 CPMM**：`buy` 价格偏移、手续费、`addLiquidity` / `removeLiquidity`。
- **多结果**：多 outcome 下注、按池比例分配。
- **预言机**：时间锁两阶段、多签 propose + approve。
- **DID**：`bindDid` + `resolveDid`。

#### （4）边界测试

- 最小下注金额（CPMM 需注意整数除法导致 shares=0）。
- outcome 索引首尾（0、N-1）。
- 多结果市场 2/8 个 outcome 极限。
- 单侧池结算、最大下注额 `maxBetPerUser`。

#### （5）错误测试

使用 `vm.expectRevert("reason")` 或 `vm.expectRevert(bytes("reason"))` 断言回滚：

- 权限：非 owner、非 oracle。
- 状态：市场已关闭、重复 claim。
- 参数：无效 outcome、零金额、过去 endTime。

#### （6）事件测试

```solidity
// vm.expectEmit(checkTopic1, checkTopic2, checkTopic3, checkData, emitter)
vm.expectEmit(true, false, false, true, marketAddr);
emit PredictionMarket.Bought(alice, 0, amount);
vm.prank(alice);
market.buy(0, amount);
```

**注意**：工厂创建市场时，合约地址为运行时部署结果，事件测试通常**只校验 marketId 等 indexed 字段**，不校验动态 market 地址。

#### （7）Gas 测试

```solidity
uint256 gasBefore = gasleft();
// ... 执行操作 ...
uint256 gasUsed = gasBefore - gasleft();
assertTrue(gasUsed > 0 && gasUsed < UPPER_BOUND);
```

也可用 `forge test --gas-report` 生成汇总报告。

| Cheatcode | 用途 | 示例场景 |
|-----------|------|----------|

## 4. 运行方式

### 4.1 环境要求

- **Foundry**：`forge` 1.x（本项目在 `forge 1.7.1` 验证通过）
- **Node.js**：用于 `node_modules` 中 OpenZeppelin 依赖
- Windows 若 `forge` 不在 PATH：

```powershell
$env:PATH = "$env:USERPROFILE\.foundry\bin;$env:PATH"
```

### 4.2 常用命令

```bash
# 进入项目根目录
cd contracts

# 运行全部 Foundry 测试
forge test

# 或通过 npm script
npm run test:foundry

forge test -vvv

# 仅运行某个合约的测试
forge test --match-contract PredictionMarketTest

# 仅运行某个用例
forge test --match-test test_Buy_yesUpdatesPool

# Gas 报告
forge test --gas-report
npm run test:foundry:gas

# 失败用例重跑
forge test --rerun

# 编译（不运行测试）
forge build
```

### 4.4 故障排查

| 现象 | 原因 | 处理 |
|------|------|------|
| `forge` 命令不存在 | 未安装或未加入 PATH | 安装 Foundry 并配置 PATH |
| `Source "contracts/XXX.sol" not found` | remapping 缺失 | 检查 `foundry.toml` 中 `contracts/=contracts/` |
| `Member "expectRevert" not unique` | 字符串重载歧义 | 改用 `vm.expectRevert(bytes("msg"))` |
| 事件 log mismatch | 动态地址与 expect 不一致 | 关闭 topic2 校验或只校验 indexed 字段 |

### 5.2 对比

| 维度 | Hardhat 测试 | Foundry 测试 |
|------|-------------|-------------|
| 语言 | JavaScript | Solidity |
| 位置 | `test/*.js` | `test/foundry/*.t.sol` |

| 场景 | 推荐框架 |

### 5.4 Hardhat 与 Foundry 用例对照

| 业务场景 | Hardhat 文件 | Foundry 文件 |

## 6. 测试代码详细注释说明

以下摘录已添加中文 NatSpec 与分区注释的核心代码，完整源码见 `test/foundry/`。

### 6.1 BaseSetup — 公共基类

```solidity
/// @title BaseSetup
/// @notice Foundry 测试基类：提供统一账户、常量与部署辅助函数
/// @dev 所有测试合约继承此类，在各自 setUp() 中调用 _deployPhase2Stack 或 _deployPhase3Stack
///      设计原则：每个测试用例通过独立 setUp 获得干净链上状态，保证隔离性与可重复性
abstract contract BaseSetup is Test {
    uint256 internal constant USDC_UNIT = 1e6;   // 1 USDC（6 decimals）

    /// @notice 初始化测试账户；子类必须调用 super.setUp()
    function setUp() public virtual {
        owner = makeAddr("owner");
        oracle = makeAddr("oracle");
        // ...
    }

    /// @notice 部署 Phase2 技术栈：MockUSDC + OracleAdapter + MarketFactory
    /// @param timelockDelay 结算时间锁秒数；0 表示可使用 resolveNow 快速路径
    function _deployPhase2Stack(uint256 timelockDelay) internal {
        vm.startPrank(owner);
        usdc = new MockUSDC();
        adapter = new OracleAdapter(owner, timelockDelay);
        adapter.grantOracle(oracle);
        factory = new MarketFactory(address(usdc), address(adapter));
        vm.stopPrank();
    }

    /// @notice 为 DIDRegistry.bindDid 生成 EIP-191 个人签名
    /// @dev 消息格式与合约一致：keccak256("BindDID:" + account + didHash)
    function _signBindDid(address account, bytes32 didHash, uint256 privateKey)
        internal pure returns (bytes memory signature)
    {
        bytes32 hash = keccak256(abi.encodePacked("BindDID:", account, didHash));
        bytes32 digest = keccak256(abi.encodePacked("\x19Ethereum Signed Message:\n32", hash));
        (uint8 v, bytes32 r, bytes32 s) = vm.sign(privateKey, digest);
        return abi.encodePacked(r, s, v);
    }
}
```

### 6.2 PredictionMarket — 典型测试结构

```solidity
/// @title PredictionMarketTest
/// @notice Phase2 二元彩池市场（parimutuel）完整测试套件
contract PredictionMarketTest is BaseSetup {
    /// @notice 每个测试前独立部署市场；timelock=0 便于直接 resolve
    function setUp() public override {
        super.setUp();
        _deployPhase2Stack(0);
        endTime = _futureEndTime(ONE_WEEK);
        (market, marketAddr) = _createBinaryMarket(endTime);
        _mintAndApprove(alice, marketAddr, 1000 * USDC_UNIT);
    }

    // =========================================================================
    // 功能测试：下注、结算、领奖
    // =========================================================================
    function test_ResolveAndClaim_winnerGetsFullPool() public {
        vm.prank(alice);
        market.buy(0, 100 * USDC_UNIT);
        vm.prank(bob);
        market.buy(1, 100 * USDC_UNIT);

        // 市场 oracle 指向 Adapter 合约地址，故用 adapter 身份 resolve
        vm.prank(address(adapter));
        market.resolve(0);

        uint256 before = usdc.balanceOf(alice);
        vm.prank(alice);
        market.claim();
        // 彩池分配：alice 押 Yes 赢，获得双方总池 200 USDC
        assertEq(usdc.balanceOf(alice), before + 200 * USDC_UNIT);
    }

    // =========================================================================
    // 错误测试：截止时间后禁止下注
    // =========================================================================
    function test_RevertWhen_buyAfterEndTime() public {
        vm.warp(endTime); // 快进到截止时间
        vm.prank(alice);
        vm.expectRevert("ended");
        market.buy(0, 10 * USDC_UNIT);
    }

    // =========================================================================
    // 事件测试：vm.expectEmit 校验 Bought
    // =========================================================================
    function test_Event_bought() public {
        uint256 amount = 25 * USDC_UNIT;
        // (checkTopic1=user, checkData=amount)
        vm.expectEmit(true, false, false, true, marketAddr);
        emit PredictionMarket.Bought(alice, 0, amount);
        vm.prank(alice);
        market.buy(0, amount);
    }
}
```

### 6.3 OracleAdapter — 时间锁流程

```solidity
function test_RequestAndConfirmResolve_timelockedFlow() public {
    vm.prank(oracle);
    adapter.requestResolve(marketAddr, 0);

    // public mapping 返回元组，需解构而非 struct 赋值
    (uint8 outcome, uint256 executeAfter, bool active) = adapter.pending(marketAddr);
    assertTrue(active);
    assertEq(executeAfter, block.timestamp + 120);

    vm.warp(block.timestamp + 121); // 满足时间锁
    vm.prank(oracle);
    adapter.confirmResolve(marketAddr);
    assertEq(uint8(market.status()), uint8(PredictionMarket.Status.Resolved));
}
```

### 6.5 PredictionMarketV3 — CPMM 边界注意

```solidity
function test_Buy_smallAmount() public {
```

### 6.6 注释规范（新增用例时请遵循）

1. **文件头**：`@title` + `@notice` 说明被测合约与阶段。
2. **setUp**：`@notice` 说明部署策略与关键参数。
3. **分区块**：用 `// ===...===` 分隔六类测试。
4. **非显而易见逻辑**：行内中文注释（如 oracle 地址、彩池公式、CPMM 精度）。
5. **避免冗余**：不断言 `assertTrue(1==1)` 类废话注释。
